# Vantage feature review for CloudLens

Reviewed 26 October 2026. Local notes only, as requested. No Figma edits or application changes made during this review.

Evidence: the six supplied official feature pages, 18 embedded product/feature images inspected visually, the user's network-flow screenshot and official Network Flow Reports documentation. These pages contain illustrative marketing examples, not a tested authenticated session. Do not treat example amounts or every illustration as production calculation evidence. Source/page inventory is in `sources.json`; inspected image references are in `screens.json`.

## Cross-page interaction and information observations

- A recognisable report shell persists across feature examples: workspace context, named report, report tabs, compact controls, primary visualization and supporting table.
- Saving is a report-level action in the header. Date, filter and grouping controls are placed beside the analysis they affect.
- Filters express dimensions, operators and values. Rule rows make multiple conditions legible. A scoped resource count provides useful feedback.
- Charts and tables answer complementary questions: visual composition/trend/relationships above, exact entities and amounts below. Previous-period values and deltas are present where comparison matters.
- Quiet neutral surfaces and thin borders hold dense information. Accent identifies selection/action; series colors distinguish data. CloudLens should preserve its approved orange DS rather than inherit Vantage's purple brand.
- These are observations of published examples. Rendering speed, keyboard behavior and state persistence were not tested.

## Six feature findings and CloudLens implications

### Virtual tagging

The examples show rule-based custom allocation and a tag-grouped cost report, connecting classification work to reporting. The page also documents cross-provider normalization, shared-cost allocation, historical reassignment and change tracking.

CloudLens proposal: begin with understandable team, environment and workload ownership. Keep unmatched spend visible. An allocation rule needs an explanation, effective date and history. A virtual label in the portal must not imply modification of AWS resource tags. Full allocation-rule tooling can follow the core investigation workflow.

[Source](https://www.vantage.sh/features/virtual-tagging)

### Budgets

The budget list emphasizes named budgets, period performance and creator. A report example puts spending and its budget together; period configuration has its own compact table. The page documents time-bound targets, alert channels, imports and hierarchical planning.

CloudLens proposal: use a scoped budget inventory with actual, target, forecast variance and owner. Opening a budget should show its spend trajectory and thresholds. Preserve its scope into the cost report. Import and enterprise hierarchy are not immediate requirements.

[Source](https://www.vantage.sh/features/budgets)

### Unit costs

A report pairs spending with a unit metric; a separate business-metric table exposes the dated denominator. The page documents importing business/technical volumes and associating them with reports.

CloudLens proposal: expose cost per transaction, request or customer only for a client scenario with a relevant, consistent denominator. Keep numerator scope, denominator source and time window inspectable. Higher total cost with better efficiency should not automatically be presented as waste. Do not copy the illustrative screenshot values as financial logic.

[Source](https://www.vantage.sh/features/unit-costs)

### Canvas

The page illustrates a prompt-led report builder and outputs that combine business dimensions, spend and outcome metrics. The report question is explicit rather than hidden behind a generic assistant surface.

CloudLens proposal: prioritize a few trusted advisory questions and client-review outputs. Generated content needs inspectable sources and calculations. A general prompt-to-dashboard builder would expand scope before our underlying evidence model is ready.

[Source](https://www.vantage.sh/features/canvas)

### Network Flow Reports

The user-supplied screenshot places filter, grouping, direction, weight and dates above a Sankey, with a traffic/cost table below. The diagram connects sources, traffic categories and destinations. Official documentation confirms selectable cost/bytes weighting, matching table groupings and resource metadata drill-down. Cost figures are estimates based on traffic and transfer rates; flow logs supply evidence beyond billing totals.

CloudLens proposal: use this treatment for an evidence-backed network-cost investigation. Model source, destination, category, interval, bytes and estimated cost. Keep the selected weight explicit and reconcile diagram links to the table. Support a route from a transfer-cost anomaly into that scope. A bill-total record alone cannot produce this network attribution. A hierarchy-only allocation Sankey would answer a different question and must be labelled accordingly.

[Feature page](https://www.vantage.sh/features/network-flow-reports), [Network Flow Reports documentation](https://docs.vantage.sh/network_flow_reports)

### Cost reports

The examples foreground a named report, compact rule filters, period/grouping controls, accrued cost and forecast, then a chart and a table with current/previous costs and change. The page documents reusable reporting, notifications and dashboard composition.

CloudLens proposal: make the scoped analysis/report the connective object between overview, investigation, budget and export. Saved reports should represent recurring questions, not simply downloaded files. Display both dollar and percentage change; sort change contributors when the task is explaining an increase.

[Source](https://www.vantage.sh/features/cost-reports)

## Proposed order for the next product update

1. Agree the report/query contract: client, dates, cost basis, grouping, filters and completeness.
2. Rework the primary overview around financial position, explained change and pending decisions.
3. Make charts, tables, drill-downs and exports share the same scope.
4. Add a coherent network anomaly scenario and a purpose-built Sankey investigation.
5. Introduce ownership allocation and unit economics only with the records needed to justify them.

This is a recommendation, not an implemented change or a commitment to replicate Vantage's feature breadth.
